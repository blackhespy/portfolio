Overview

What is Apothecaria?

Apothecaria is a full-featured pharmacy management desktop application designed for small-to-medium Indonesian pharmacies. It runs entirely offline — all data is stored locally in a SQLite database — making it reliable in environments with poor or no internet connectivity.

The system handles every core pharmacy workflow: from cataloguing drugs and managing stock levels, to running a point-of-sale cashier, tracking stock mutations, monitoring cash flow, and analyzing product margins.

Key Design Decision: Offline-First

Unlike cloud-based SaaS systems, Apothecaria runs entirely on the local machine. All data lives in a WAL-mode SQLite database with foreign key enforcement. The app is packaged as an NSIS Windows installer for one-click deployment — no server setup, no subscriptions, no internet required.

Dashboard — daily greeting, 4 key metrics, 30-day cash flow chart, asset breakdown by category, and critical items alert

Architecture

The app follows Electron's secure IPC architecture — the React renderer process communicates with the main process exclusively through a contextBridge preload, keeping the renderer sandboxed from Node.js APIs.

Renderer Process (React + Vite)
    └── src/lib/api.js     ← window.electronAPI wrapper

Main Process (Electron + Node.js)
    └── electron/main.js     ← IPC handlers, window management
    └── electron/db/
        ├── database.js     ← SQLite init + WAL mode
        ├── migrations.js   ← schema versioning
        └── handlers/
            ├── products.js   ← CRUD + stock
            ├── movements.js  ← stock mutations
            ├── sales.js      ← POS transactions
            └── cashflow.js   ← manual cash entries

Core Modules

Module 01

Dashboard

Daily overview with 4 key metrics, 30-day area chart (cash in vs out), asset pie chart by drug category, and critical stock/expiry alerts.

Module 02

Drug Master

Full product catalog with SKU, batch, category, stock vs minimum, COGS, sell price, auto-calculated margin %, and expiry date tracking.

Module 03

Point of Sale

Two-panel cashier UI — product grid left, cart right. Cash/QRIS/Transfer payment, receipt printing, unique transaction IDs, real-time stock deduction.

Module 04

Cash Flow

Full cash tracking with daily bar chart, payment channel breakdown (QRIS, Cash, Transfer, EDC), and manual entry for operational expenses.

Module 05

Stock Mutations

Complete audit trail for every stock movement: opening, purchase, sale, adjustment, expiry. Filter by type, reprint receipts from any sale entry.

Module 06

Margin Analysis

Profitability dashboard by period (7/30/90d/YTD). Top 10 profit contributors via horizontal bar chart. Revenue, gross profit, margin % per SKU or category.

Drug Master — full inventory table with SKU, batch, category pills, stock status, COGS, sell price, margin %, and expiry countdown

Point of Sale

The cashier module uses a two-panel layout: the left side shows a filterable product grid, the right side is the live shopping cart. Transactions are atomic — a single sale simultaneously:

  • Writes a record to the sales table with full item JSON
  • Decrements stock for each product sold
  • Creates a cash inflow entry in cashflow
  • Records a stock mutation of type out in movements
  • Generates a printable thermal receipt (280px width, monospace)
Cashier module — product grid, cart, payment methods, and receipt generation
Stock mutations — full audit trail with type badges, qty signs, and receipt reprint

Cash Flow & Financial Tracking

Every sales transaction automatically creates a cash inflow entry. Pharmacists can also manually log operational expenses (supplier purchases, utilities, salaries) as outflow entries. The finance module visualizes:

  • Total Inflow / Outflow / Net Cash — summary cards with margin %
  • 30-day daily bar chart — inflow vs outflow side by side
  • Payment channel breakdown — QRIS, Cash, Transfer, EDC BCA, EDC Mandiri
  • Full transaction history table — filterable, sortable entries
Cash & Financial Flow — inflow/outflow summary, 30-day bar chart, and channel payment breakdown

Database Schema

Four core tables with WAL mode and foreign key enforcement for data integrity:

TableKey Fields
productsSKU, name, brand, category, unit, batch, stock, min_stock, COGS, sell_price, expiry, supplier
movementsID, date, type (in/out/adj/exp/opening), product_id, qty, COGS value, reference, actor
salesTransaction ID, date, items (JSON), subtotal, discount, total, payment method, cashier
cashflowID, date, type (in/out), label, channel, amount
